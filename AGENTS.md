# Repository Guidelines

## Project Structure & Module Organization
`wordfeatures` is an R package with a companion research workflow. Core package code lives in `R/`, including API-facing files such as `R/word_embeddings.R` and `R/imageability.R`. Packaged datasets are stored in `data/` as `.rda` files. Regeneration scripts and source ingesters live in `data-raw/`. Package-development and artifact-building workflows live in `analysis/`. Research-facing benchmark, audit, and expansion scripts live in `research/` and are kept out of the built package. Generated documentation is in `man/`, and package metadata is defined in `DESCRIPTION` and `NAMESPACE`.

## Build, Test, and Development Commands
Run commands from the repository root.

- `R -q -e "devtools::document()"`: rebuild `NAMESPACE` and `man/` from roxygen comments.
- `R -q -e "devtools::test()"`: run the package test suite.
- `R CMD build .`: create a source tarball for the package.
- `R CMD check wordfeatures_1.0.tar.gz`: run package checks on the built tarball.
- `R -q -e "source('data-raw/glasgow_norms.R')"`: regenerate `data/glasgow_norms.rda`.
- `R -q -e "source('data-raw/sensorimotor_norms.R')"`: regenerate `data/sensorimotor_norms.rda`.
- `Rscript data-raw/imageability_training_frame.R`: rebuild the merged modeling frame.
- `Rscript analysis/train_imageability_model_bundle.R`: retrain and package the bundled imageability model.
- `Rscript research/benchmarks/run_cognitive_alignment_benchmark.R`: run the fixed-fold research benchmark.
- `Rscript research/audit/run_norm_audit.R`: generate overlap and disagreement tables across norm sources.
- `Rscript research/expansion/run_norm_expansion.R`: run held-out norm-expansion experiments.

## Coding Style & Naming Conventions
Follow the existing base-R style: 2-space indentation inside functions, one logical step per block, and explicit namespace calls such as `dplyr::rename()` when a package is not imported broadly. Use `snake_case` for object and function names (`predict_imageability`, `glasgow_processed`). Keep roxygen comments directly above exported functions, and do not edit `NAMESPACE` by hand because it is generated by `roxygen2`.

## Testing Guidelines
Tests live under `tests/testthat/` and use `testthat` edition 3. Run `devtools::test()` before opening a PR and use `R CMD check` for package-level verification. For changes to data-processing scripts, rerun the relevant `data-raw/*.R` script, rebuild any downstream package artifacts in `analysis/`, and verify the resulting `.rda` objects load cleanly. Keep research outputs under `research/results/` rather than mixing them into package directories. Name tests after the feature being checked, for example `test-imageability-bundle.R`.

## Commit & Pull Request Guidelines
Git history is not available in this snapshot, so use short imperative commit messages such as `Add Google embedding error handling` or `Regenerate Glasgow norms data`. Keep commits focused. PRs should describe the user-visible change, list any regenerated data or documentation, note required API keys (`OPENAI_API_KEY`, `GOOGLE_API_KEY`), and include check results from `R CMD check`.

## Configuration Tips
Do not hard-code secrets. Read API credentials from environment variables, matching the package code (`OPENAI_API_KEY`, `GOOGLE_API_KEY`, `GEMINI_API_KEY`). Keep `.env` out of package builds. When changing embedded-model behavior, document the provider and model defaults in roxygen, `README.md`, and the PR description.
